# Screen review checklist

Review the exported screenshot and actual HTML together before claiming the design is ready.

- Recognizably native Android composition, using the approved playful design system; primary controller should differ structurally from the rejected dark card stack.
- Target and measured room temperature visually distinct; no ambiguous degree units or fabricated sensors.
- Power and AC display easy to find and clearly separate; display state/action not confused with whole-unit power.
- Four advertised modes only: Auto, Cool, Dry, Fan. Any selected mode draft has explicit Apply before dependent settings.
- Visible fan setting and a compact path to more controls/readings; no invented schedules or live graphs.
- Everyday copy stays concise. Protocol explanations belong in help/spec, not the remote face.
- Controls fit without clipping or overlap; target areas at least48dp; text has readable contrast. Native text scaling/insets remain implementation checks.
- Widget status has an observation time, explicit current power state and action, no simultaneous pending/error. Proposed display action labeled outside the specimen.
- Exported HTML/screenshot are design specimens. Do not present them as a tested native build or working API controls.
